# Lab3-3 笔记：DPI-C 差分测试的本质理解

## 1. 背景：为什么需要差分测试

写完一个乘法器或除法器后，最直接的问题是：

> 我怎么知道它算得对？

只看波形不够。波形只能说明某几个时刻的信号变化看起来合理，但不能系统性证明结果正确。

手工算几个例子也不够。32 位乘法输入空间太大，不可能人工穷举。随机测试能覆盖更多输入，但仍然需要一个东西来判断“当前输出到底对不对”。

这时就需要参考模型。

参考模型可以理解为“另一套独立计算答案的方法”。在 Lab3 中，被测对象是 Verilog 写的硬件乘法器，参考模型是 C 函数。二者处理同一组输入，然后比较输出。

这就是差分测试。

---

## 2. 差分测试是什么

差分测试（Differential Testing）的核心很简单：

> ==同一个输入，交给两个独立实现，比较输出是否一致。==

在实验里，流程大致是：

```text
随机输入 a, b
        ↓
Verilog 乘法器计算实际结果
        ↓
C 函数计算参考结果
        ↓
Judge 模块比较二者
        ↓
一致：通过；不一致：报错
```

它不要求你提前手写每个输入对应的标准答案，而是用另一个实现现场生成答案。

所以差分测试本质上回答的是：

> 两个独立实现对同一问题的回答是否一致？

---

## 3. 它不是正确性证明，而是置信度工具

差分测试有一个必须讲清楚的点：它不能数学证明你的电路一定正确。

如果两个实现输出不一致，可以确定：

> 至少有一个实现错了。

但如果两个实现输出一致，只能说明：

> 它们大概率都对。

因为仍然存在一种可能：两个实现犯了同样的错误，输出刚好一致。

所以差分测试降低的是**漏报概率**，不是给出形式化正确性证明。

更精确地说：

- 不一致：确定发现问题；
- 一致：增强正确性信心；
- 独立性越强，“一起错且错得一样”的概率越低。

这就是为什么差分测试是一种工程上很实用的验证方法：它不完美，但成本低、覆盖广、发现 bug 的能力强。

---

## 4. 独立性为什么重要

差分测试的有效性来自两个实现之间的独立性。

如果两个实现太像，它们可能一起犯同样的错误。比如都用 SystemVerilog 写，都依赖同一种位宽规则、同一种截断行为、同一种符号扩展语义，那么很多错误会被共同继承。

这时即使对拍一致，也不一定说明真的正确。

因此，参考模型最好在多个层面上和被测实现不同：

| 独立维度 | 例子 | 作用 |
|---|---|---|
| 语言独立 | C vs Verilog | 避免共享同一套语言陷阱 |
| 算法独立 | 直接乘法 vs 迭代加法 | 避免共享同一套算法错误 |
| 结构独立 | 软件模型 vs 硬件状态机 | 避免共享同一套时序实现 |
| 开发独立 | 不同人实现 | 避免共享同一套思维盲区 |

Lab3 用 C 函数做参考模型，价值不只是“C 算起来方便”，更重要的是它提供了一个和 Verilog 电路不同的语义环境。

---

## 5. 为什么不用 Verilog function 做参考模型

表面上看，Verilog function 也能写一个乘法函数：

```verilog
function [63:0] ref_mul;
    input [31:0] a;
    input [31:0] b;
    begin
        ref_mul = a * b;
    end
endfunction
```

这样当然能算，但它有两个问题。

第一个问题是：它和被测电路共享 Verilog 的语言语义。

比如：

- 位宽自动扩展；
- 截断规则；
- signed / unsigned 处理；
- 拼接后的位宽；
- 移位时高位如何补；
- 表达式结果宽度由谁决定。

这些恰好都是硬件实验里最容易出错的地方。如果参考模型也用 Verilog 写，它可能和 DUT 一起踩同一个坑。这样二者输出一致，bug 反而被掩盖。

第二个问题是：普通 Verilog function 不适合模拟跨周期状态。

function 更像一个组合计算过程：输入进去，立即返回结果。函数调用结束后，局部变量就消失了。它没有天然的跨调用持久记忆。

但时序电路的核心恰恰是跨周期记忆。乘法器每一拍都要保留：

- 当前部分积；
- 当前乘数；
- 当前计数器；
- 当前 FSM 状态。

这些信息不是一次调用内部的临时变量，而是跨时钟周期持续存在的寄存器状态。

所以，如果要用 Verilog function 模拟整个时序过程，就会很别扭：它很容易退化成“直接算答案”，而不是模拟和 DUT 对齐的时序参考行为。

---

## 6. C 函数相对于 function 的优势

C 函数至少有两层优势。

### 6.1 语言边界带来的独立性

C 的整数计算语义和 Verilog 不同。

例如在 C 里写：

```c
unsigned long long result = (unsigned long long)a * b;
```

这个表达式的语义很清楚：把 `a` 提升到 64 位无符号整数，再做无符号乘法，得到 64 位结果。

它不会受 Verilog 拼接、非阻塞赋值、表达式位宽推导等规则影响。

这就让 C 参考模型成为一个更独立的参考系。如果 Verilog 电路因为位宽写错、移位写错、拼接写错导致结果异常，C 那边不会跟着犯同样的错误。

### 6.2 `static` 变量可以保存跨调用状态

C 函数可以用 `static` 变量记住上一次调用留下的信息：

```c
static unsigned long long expected_result;
```

`static` 变量不会随着函数返回而销毁，下一次调用时仍然保留上一次的值。

这点对时序对拍很有用。因为硬件电路也是跨周期保存状态的：寄存器不会在一个函数调用结束后消失，而是等下一拍继续参与计算。

当然，如果参考模型只是直接计算 `a * b`，不一定非要 `static`。但一旦需要模拟“先返回上一拍结果，再更新当前结果”这类时序对齐行为，`static` 就非常自然。

所以 C 函数相比 Verilog function，不只是“能算乘法”，而是更容易写出一个和硬件时序对齐、同时又语义独立的参考模型。

---

## 7. DPI-C 在这里起什么作用

DPI-C 可以理解成 SystemVerilog 和 C 之间的接口桥梁。

Verilog testbench 或 `Judge` 模块可以通过 DPI 调用 C 函数，把输入传给 C，再拿回 C 算出的参考结果。

大致逻辑是：

```verilog
import "DPI-C" function longint unsigned ref_mul(
    input int unsigned a,
    input int unsigned b
);
```

然后在验证模块里调用：

```verilog
expected = ref_mul(multiplicand, multiplier);
```

这样，硬件侧负责跑 DUT，C 侧负责算参考答案，`Judge` 负责比较。

DPI-C 的价值在于：它让两个不同语言世界可以在同一个仿真流程中协作。

---

## 8. Judge 模块的作用

`Judge` 模块不是乘法器的一部分，它是验证环境的一部分。

它的任务是：

1. 接收 DUT 的输出结果；
2. 调用或接收 C 参考模型的结果；
3. 在 `finish` 有效时比较二者；
4. 如果不一致，拉高 `error` 或打印错误信息。

为什么要在 `finish` 时比较？

因为 `finish` 之前，DUT 输出可能只是中间值。只有 `finish = 1` 时，输出才具有最终结果语义。

这点和握手协议是连在一起的：验证也必须尊重被测模块的协议。不能在结果未完成时比较，否则会把正常中间态误判成错误。

---

## 9. 为什么随机测试适合配合差分测试

差分测试常和随机输入一起使用。

原因是输入空间太大，人工挑几个例子覆盖不够。随机测试可以快速生成大量不同输入，让电路经历更多情况。

但随机测试本身只负责“产生输入”，不能判断输出是否正确。差分测试提供了判断标准。

两者结合起来就是：

> 随机测试负责扩大覆盖面，差分测试负责自动判对错。

不过随机测试也不是万能的。它可能很久都碰不到边界情况，所以还需要补充特殊输入，例如：

- `0 × x`；
- `1 × x`；
- `0xffffffff × x`；
- 高位全 1；
- 低位全 1；
- 只有单个 bit 为 1；
- 接近溢出边界的输入。

这些边界用例能专门攻击位宽、移位、进位、符号扩展等常见 bug。

---

## 10. 差分测试的局限

差分测试的局限主要有三个。

第一，它不能证明正确。

一致只能说明两个实现对这组输入输出相同，不能覆盖所有输入，也不能排除共同错误。

第二，它依赖参考模型质量。

如果 C 模型本身写错了，DUT 可能被误判。尤其是参考模型为了模拟时序而写得很复杂时，参考模型也会成为 bug 来源。

第三，它依赖输入覆盖。

没测到的输入，差分测试无法发表意见。随机测试提高覆盖概率，但不能替代完整证明。

所以差分测试适合工程验证，但不等同于形式验证。

形式验证更像是数学证明，能在规约完整、状态空间可控的情况下给出更强保证；差分测试更像是用大量样本建立信心，成本低，适合实验和工程迭代。

---

## 11. 本质理解：差分测试是在制造“对照组”

差分测试的本质不是 C，也不是 DPI，而是“对照组”。

一个实现单独跑，你只能看到它输出了什么，却不知道它应不应该这么输出。

两个独立实现一起跑，你就可以用它们之间的差异暴露问题。

这里最关键的是“独立”。如果两个实现不独立，就像两个人抄同一份错误答案，对答案没有意义。只有当两个实现的错误来源不同，对拍一致才有较高可信度。

所以差分测试真正训练的思维是：

> ==不要只相信一个实现，要用独立参考系校验它。==

---

## 12. 和实验中乘法器的关系

Lab3 的乘法器是一个典型的时序实现：每一拍处理乘数的一位，逐步累加部分积，最后得到 64 位乘积。

C 参考模型则可以直接使用 64 位无符号乘法，一步得到结果。

这两个实现的路径不同：

| 实现 | 计算方式 | 特点 |
|---|---|---|
| Verilog DUT | 多周期迭代累加 | 接近真实硬件结构 |
| C 参考模型 | 直接 64 位乘法 | 语义简单，适合做标准答案 |

正因为两者路径不同，对拍才有意义。

如果 Verilog 乘法器的移位方向错了、计数器少跑一轮、部分积拼接错了，C 模型不会跟着错，于是 `Judge` 能发现不一致。

---

## 13. 思维提升：验证不是“看起来对”，而是建立证据链

很多初学者写硬件时，容易停留在“波形看起来差不多”的层面。但工程验证不能靠感觉。

更可靠的验证应该形成证据链：

1. 输入是怎么产生的；
2. 什么时候输入有效；
3. DUT 什么时候输出有效；
4. 参考答案由谁生成；
5. 在哪个时刻比较；
6. 不一致时如何定位。

差分测试把这条链自动化了。

它让验证从“我看波形觉得对”变成“每组输入都有独立参考模型对拍”。这就是工程验证意识的提升。

---

## 14. 一句话总结

差分测试就是用两个独立实现处理同一输入，通过比较输出降低漏错概率。DPI-C 的价值在于引入 C 参考模型这个独立参考系，使 Verilog 电路的位宽、移位、时序等错误更容易暴露出来。
