## C 语言核心代码

```c
#include <stdio.h>
#include <stdlib.h>

// 链表节点标准定义
struct ListNode {
    int val;
    struct ListNode *next;
};

struct ListNode* mergeTwoLists(struct ListNode* l1, struct ListNode* l2) {
    // 1. 祭出假头节点：彻底统一插入逻辑，无需判断头节点是否为空
    struct ListNode dummy;
    dummy.next = NULL;
    
    // tail 指针负责在前面开路，永远指向当前合并链表的最后一个有效物理节点
    struct ListNode* tail = &dummy;

    // 2. 核心火拼区：只有当双方都有剩余兵力时，才需要进行比较
    while (l1 != NULL && l2 != NULL) {
        if (l1->val <= l2->val) {
            tail->next = l1;  // 挂载 l1 的当前节点
            l1 = l1->next;    // l1 的战线向后推移
        } else {
            tail->next = l2;  // 挂载 l2 的当前节点
            l2 = l2->next;    // l2 的战线向后推移
        }
        tail = tail->next;    // 尾指针永远跟进到刚刚挂载的新节点上
    }

    // 3. O(1) 终极收尾：此时必然至少有一个链表已经弹尽粮绝
    // 剩下的那个链表无论多长，本身绝对是有序的，直接用一根指针整串接盘
    if (l1 != NULL) {
        tail->next = l1;
    } else {
        tail->next = l2;
    }

    // 返回假头节点背后的真正头节点
    return dummy.next;
}

```

- **唯一消耗点（while 循环）：** 代码中的 `while (l1 != NULL && l2 != NULL)` 是产生所有比较操作的唯一发生地。如果是我们在上一个问题中推演的“一边倒”极端场景，某一个链表在 `N` 次循环后就会率先变成 `NULL`，从而瞬间击穿这个 `while` 循环的防线。

## 1. 为什么最大比较次数是 2N - 1？
在链表合并中，每次比较操作的核心物理意义是：**在两个候选节点中决出一个较小值，并将其放入最终的合并链表中。**
合并后的链表总共有 2N 个节点。要达到“最大比较次数”，前提是两个链表的元素必须像拉链一样**完美交错**（例如 A = [1, 3, 5], B = [2, 4, 6]）。在这种极端的拉锯战中，没有任何一方能迅速被消耗殆尽。
**执行推演（以 N=3 为例）：**

1. 比较 1 和 2：1 胜出出列。（第 1 次比较）
2. 比较 3 和 2：2 胜出出列。（第 2 次比较）
3. 比较 3 和 4：3 胜出出列。（第 3 次比较）
4. 比较 5 和 4：4 胜出出列。（第 4 次比较）
5. 比较 5 和 6：5 胜出出列。（第 5 次比较，即 2N - 1 次）
此时，A 链表终于耗尽。B 链表仅剩的最后一个元素 6，无需再和任何人比较，直接通过指针挂载到合并链表的尾部。
**总结：** 为了放置前 2N - 1 个节点，系统必须进行 2N - 1 次比对。最后的第 2N 个节点是因为无人在场而自动落位的。只有在最好的“一边倒”情况下，比较次数才是 N。

## 2. 引入：合并 K 个有序链表
当待合并的链表数量从 2 个扩展到 K 个时，传统的双指针两两比较策略会导致极高的重复比对开销。在工业级架构中，解决多路归并的标准数据结构是**最小堆（Min-Heap / 优先队列）**。
**核心运作机制：**

1. **初始化（建堆）：** 取出 K 个链表的第一个节点（头节点），将它们全部压入一个容量限制为 K 的最小堆中。由于堆的特性，此时堆顶的节点必定是这 K 个节点中的**全局最小值**。
2. **提取与挂载：** 弹出堆顶的全局最小节点，将其追加到最终的合并链表尾部。
3. **节点递进补充：** 检查刚刚被弹出的节点，如果它所在的原始链表还有下一个节点，则将那“下一个节点”压入堆中。堆会自动调整结构（向上/向下渗透），重新选出新的全局最小值在堆顶。
4. **循环：** 持续执行提取和补充操作，直到堆被完全清空。
**复杂度评估：**

- **时间复杂度：**`O(T * log K)`。其中 `T` 是所有链表的节点总数（若每个链表长 N，则 `T = N * K`）。每次将一个新节点压入或弹出堆的调整代价是 `O(log K)`，该动作共计执行 `T` 次。
- **空间复杂度：**`O(K)`。无论底层有多少万个节点，内存中维护的最小堆的大小永远被严格控制在链表的条数 K 以内。
