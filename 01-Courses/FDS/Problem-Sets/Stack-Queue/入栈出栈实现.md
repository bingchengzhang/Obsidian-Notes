## 1. 核心数据结构定义
根据幻灯片第 3 页的定义，一个良好封装的栈结构体包含三个要素：

```c
typedef int ElementType; // 假设栈里存的是整数

struct StackRecord {
    int Capacity;       /* 栈的最大容量 */
    int TopOfStack;     /* 栈顶指针：空栈时为 -1，Push时++，Pop时-- */
    ElementType *Array; /* 指向实际存储数据的底层数组 */
};

typedef struct StackRecord *Stack;

```

## 2. Push（入栈）的底层逻辑
入栈的核心动作是：**先将栈顶指针上移，然后在新位置写入数据**。
但正如幻灯片第 1 页和第 3 页强调的红线：对满栈执行 Push 是实现层面的严重错误，因此必须强制进行边界预检（Error check）。

```c
void Push(ElementType X, Stack S) {
    // 强制预检：防止数组越界覆盖其他内存
    if (S->TopOfStack == S->Capacity - 1) {
        printf("Error: 栈已满 (Implementation Error)\n");
        return;
    }
    
    // 指针先上移一位，然后再将数据存入该索引位置
    S->TopOfStack++;
    S->Array[S->TopOfStack] = X;
    
    // 上面两行通常被极简压缩为一行：
    // S->Array[++S->TopOfStack] = X;
}

```

## 3. Pop（出栈）的底层逻辑
出栈的核心动作是：**直接将栈顶指针下移**。
同理，幻灯片第 1 页指出，对空栈执行 Pop 属于 ADT 逻辑崩塌，必须拦截。

```c
void Pop(Stack S) {
    // 强制预检：防止指针跌破底线变成 -2 甚至更低
    if (S->TopOfStack == -1) {
        printf("Error: 栈为空 (ADT Error)\n");
        return;
    }
    
    // 物理层面的“抹杀”仅仅是剥夺访问权
    S->TopOfStack--;
}

```
我个人认为，初看这段出栈代码时，很多人会觉得不安：“你只是把 `TopOfStack` 减了 1，数组里的数据并没有被清零或删除啊？”
这就是 C 语言极其冷酷的底层哲学：**不影响逻辑正确性的冗余操作，一概不做。**
因为只要栈顶指针降下来了，外部代码就再也无法通过合法的 `Top(S)` 函数访问到那个残留数据；而当下一次执行 `Push` 时，新数据会毫不留情地直接覆盖在这个旧数据所在的内存位置上。
