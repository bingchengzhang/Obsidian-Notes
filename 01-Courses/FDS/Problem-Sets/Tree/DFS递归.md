## 1. 递归三兄弟：代码实现
这三段代码长得几乎一模一样，唯一的区别就是你打算在什么时候“收网”（处理当前节点的数据）。

```c
// 1. 前序遍历：根 -> 左 -> 右
void preorder(tree_node* root) {
    if (!root) return;          // 刹车片：撞到 NULL 就返回
    printf("%d ", root->element); // 【根】先处理自己
    preorder(root->left);       // 【左】甩锅给左边
    preorder(root->right);      // 【右】甩锅给右边
}

// 2. 中序遍历：左 -> 根 -> 右
void inorder(tree_node* root) {
    if (!root) return;
    inorder(root->left);        // 【左】先等左边全部处理完
    printf("%d ", root->element); // 【根】再处理自己
    inorder(root->right);       // 【右】最后甩锅给右边
}

// 3. 后序遍历：左 -> 右 -> 根
void postorder(tree_node* root) {
    if (!root) return;
    postorder(root->left);      // 【左】等左边处理完
    postorder(root->right);     // 【右】等右边也处理完
    printf("%d ", root->element); // 【根】最后才轮到自己
}

```

## 2. 深度剖析：递归的代价
虽然递归写起来爽得飞起，但作为专家，我得提醒你它在物理世界的真实开销。

- **时间复杂度**：每个节点只被访问常数次，所以是 $O(N)$。
- **空间复杂度**：这是递归的“隐形账单”。虽然你没定义栈，但系统帮你开辟了调用栈。
  - 如果树是完美的平衡二叉树，高度是 $\log N$，空间复杂度是 $O(\log N)$。
  - 如果树退化成了链表（倾斜树），高度就是 $N$，空间复杂度暴涨到 $O(N)$。

## 3. 为什么递归 DFS 能“自动”完成遍历？
你可以想象成每个节点都有三条命：

1. **初次见面**：函数刚进来，对应前序位置。
2. **左路归来**：左子树递归完了，回到当前节点，对应中序位置。
3. **右路归来**：右子树也递归完了，准备退出函数，对应后序位置。
递归就是利用这三次“路过”的机会，通过调整 `printf` 的位置，实现了三种截然不同的遍历顺序。

## 专家的对冲反思
递归是**算法思维**的巅峰，但**不是工程健壮性**的巅峰。
在处理只有几十个节点的题目（比如你现在的 $N \le 30$）时，递归是绝对的神器，代码简洁且不易出错。但在生产环境（比如处理拥有百万级节点的内存数据库索引）中，我们通常会强迫自己写**迭代版**。因为系统栈的大小通常只有几 MB，一旦树太深，递归会直接引发 `Stack Overflow` 导致程序崩溃。
