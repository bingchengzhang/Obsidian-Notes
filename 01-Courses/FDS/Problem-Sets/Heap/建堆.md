这就是二叉堆工程实现中的最后一块拼图，也是极其优雅的一步：**线性建堆（BuildHeap）**。
如果你拿到一个完全乱序的数组，想要把它变成一个堆，最直观的想法是：建一个空堆，然后把 $N$ 个数字一个一个 `Insert` 进去。

- **代价**：每次 `Insert` 都要上浮，最坏情况是 $O(\log N)$。插入 $N$ 次，总时间复杂度就是 **O(NlogN)**。
但计算机科学家们极其抠门，他们发现如果直接利用完整的乱序数组进行原地“下沉”调整，可以在 **O(N)** 的时间复杂度内完成建堆。也就是所谓的“瞬间成型”。

### 1. 完整的 $O(N)$ 建堆代码
这段代码直接复用了我们之前写好的“极致下沉”函数 `PercolateDown`。假设乱序的数据已经全部放入了 `H->Elements[1]` 到 `H->Elements[N]` 中，且 `H->Size = N`。

```c
/* * 原地线性建堆 (BuildHeap)
 * 复杂度: O(N)
 * 前提: 乱序数据已经存放在 H->Elements[1...Size] 中，且 H->Elements[0] 有哨兵
 */
void BuildHeap( PriorityQueue H ) {
    int i;
    // 从最后一个非叶子节点 (N/2) 开始，倒退着一路向根节点 (1) 进发
    for ( i = H->Size / 2; i > 0; i-- ) {
        PercolateDown( i, H ); // 让每个小片区的“老领导”尝试下沉
    }
}

```
就这么极简的几行！但它的数学底蕴非常深厚。

### 2. 核心揭秘：为什么要从 $N/2$ 开始倒着算？
在完全二叉树的物理结构（数组）中，有一个铁律：
**数组下标从 ⌊N/2⌋+1 一直到 N 的所有节点，全都是叶子节点（也就是没有底层的员工了）。**

- **物理意义**：叶子节点本身就可以被看作是一个个大小为 1 的“合格的微型堆”。既然它们底下没孩子，它们根本没有“下沉”的空间和必要。
- **逆向集结**：我们从下标 $N/2$（最后一个有孩子的节点）开始倒着遍历。
  1. 走到 $N/2$ 时，让它和它的孩子比，构成一个大小为 3 的合格小堆。
  2. 继续往前走，遇到的节点相当于更高层的“老领导”。
  3. 因为我们是倒着走的，所以当老领导往下看的时候，**他底下的左右子树已经全都是严格的合格小堆了**。
  4. 此时，老领导只需要执行一次标准的 `PercolateDown`，就能把两棵合格的子树合并成一棵更大的合格树。
  5. 直到退回到根节点 `i = 1`，最后一次下沉完毕，整棵大树彻底化为二叉堆。

### 3. 直率专家的数学对冲：凭什么是 $O(N)$？
很多人凭直觉会觉得：包含一个 $O(\log N)$ 的 `PercolateDown`，外面套个 $N/2$ 次的循环，时间复杂度不该是 $O(N \log N)$ 吗？
这正是这个算法最迷人的数学骗局：**只有极少数的节点需要走最远的路。**

- **底部的节点**：虽然人多（占了整棵树的一半），但它们最多只能下沉 1 层。
- **中间的节点**：人数少了一半，最多下沉 2 层。
- **根节点**：虽然要下沉 $\log N$ 层，但根节点只有 **1** 个。
把这些步数用数列求和公式加起来（一个典型的错位相减法），得出的极限步数是 **2N**。
去掉了常数，时间复杂度就是极其惊艳的 **O(N)**。
