# 拓扑排序与最短路径算法的统一视角

## 一、问题本质

任务之间有依赖关系——A 必须在 B 之前完成。求一个合法的执行顺序。

用有向图建模：节点是任务，A→B 表示 A 必须先于 B。合法执行顺序就是一个**拓扑序**——所有边都从序列前面指向后面。

前提是 **DAG**（Directed Acyclic Graph，有向无环图）。有环就是循环依赖，不存在合法顺序。

拓扑排序描述的是**偏序关系**：只对有依赖的节点对定义顺序，无依赖的节点对顺序随意。算法把这个偏序扩展成一个全序序列——有约束的地方严格遵守，无约束的地方任意填。所以拓扑序通常不唯一。

## 二、Kahn 算法

每次找入度为 0 的节点（没有任何前置依赖），加入序列，从图里删掉它（出边全部删掉，邻居入度各减一）。重复直到图空（成功）或找不到入度为 0 的节点（有环，失败）。

```c
int indegree[MAXV];   /* 每个节点的入度，建图时同步维护 */
int queue[MAXV], front = 0, rear = 0;
int seq[MAXV], cnt = 0;

/* 初始化：所有入度为0的节点入队 */
for (int i = 1; i <= Nv; i++)
    if (indegree[i] == 0)
        queue[rear++] = i;

while (front < rear) {
    int v = queue[front++];   /* 出队 */
    seq[cnt++] = v;           /* 出队即加入序列 */

    /* 删掉 v 的出边：邻居入度各减一 */
    for (struct EdgeNode *p = graph[v]; p; p = p->next) {
        int w = p->neighbor;
        if (--indegree[w] == 0)
            queue[rear++] = w;
    }
}

if (cnt == Nv)  /* 成功，是 DAG */
else            /* 有环 */
```

`cnt != Nv` 说明有节点永远没被剥到，它们构成环。这是顺带的环检测，不需要额外算法。

## 三、关键问题澄清

### 同时入度为 0 的节点之间什么关系？

**互相独立，没有边相连**。如果它们之间有边 u→v，v 的入度必然 ≥ 1（u 还没被处理，这条边还在），所以 v 不可能同时入度为 0。

既然独立，谁先出队都合法。FIFO 队列给一种顺序，最小堆给字典序最小的拓扑序——本质是从"待处理池"里选一个，怎么选取决于需求。

### 为什么要全部入队而不是只取一个？

入队是为了追踪"当前还有哪些合法候选"。处理完一个节点后，原来那批没处理的还是合法候选，新暴露出来的也是。如果不入队保存着，下一轮就找不到它们了。

队列在这里不是"按顺序处理"的工具，而是个**待处理池**。

### 入度独立性如何保证不混淆？

每个节点维护自己的入度计数，不管被多少节点的出边指着。如果节点 E 被 A 和 B 同时指着，E 的入度是 2——A 处理时减一次，B 处理时再减一次，减到 0 才入队。**精确等待所有前驱完成**，这就是入度计数的隔离机制。

### A→C, B→D 这种情况，A 和 D 的关系？

A 和 C 有依赖，B 和 D 有依赖，但 A 和 D、B 和 C 之间没有约束。合法序列可以是 ABCD、BACD、ABDC、BADC 等，只要 A 在 C 前、B 在 D 前。

Kahn 算法给出的具体结果取决于入队顺序，这是算法自然给出的——拓扑排序本身就不定义这些无约束节点对的顺序。

### 节点会重复入队吗？

不会。每条入边只被处理一次（对应的前驱出队时减一次），入度归零的瞬间才入队，每个节点恰好入队一次，恰好出队一次。所以拓扑排序**不需要 visited 数组防重**。

## 四、与 BFS、Dijkstra 的统一视角

三个算法都用队列（或堆）保证一个核心不变式：

**出队（确定）的那一刻，节点所依赖的前置信息已经确定，且不会再变。**

| 算法     | 确定的判据         | 数据结构 | 输出       | 重复入队 |
|----------|--------------------|----------|------------|----------|
| BFS 最短路 | 第一次被发现     | FIFO 队列 | dist 数组  | 需 visited 拦截 |
| 拓扑排序 | 入度为 0           | FIFO 队列 | 节点序列   | 天然不会 |
| Dijkstra | 堆顶 + dist 匹配   | 最小堆    | dist 数组  | lazy deletion 拦截 |

### 三个算法的统一框架

抽象成一个模板就能看出共性：

```
1. 维护一个"待处理池"（队列或堆）
2. 把满足"初始条件"的节点放进池
3. while 池非空：
       从池里取一个节点 v（按某种规则）
       记录 v 已确定（输出/标记）
       遍历 v 的出边，更新邻居的状态
       邻居满足"入池条件"就放进池
```

三个算法的差异只在三个位置：

|              | 初始条件         | 取节点规则     | 入池条件             |
|--------------|------------------|----------------|----------------------|
| BFS 最短路   | source           | FIFO           | 未被 visited 标记    |
| 拓扑排序     | 入度为 0         | FIFO           | 入度减到 0           |
| Dijkstra     | source           | 堆顶（dist 最小） | 松弛成功（dist 变小） |

框架完全一样，换三个钩子就能从一个变成另一个。

### 不变式：出队即确定，确定不后悔

每个算法都靠一个不变式保证正确性：

- **BFS**：第一次发现一个节点时，它的距离就是最短。理由——FIFO 保证按层扩展，距离短的节点先入队，所以第一次入队的距离不可能被后来更长的路径超过。
- **拓扑排序**：入度归零的节点，它的所有前驱都已经出队。理由——入度减一的操作精确对应"某个前驱被处理"，减到 0 意味着所有前驱都减完了。
- **Dijkstra**：堆顶的 unknown 节点，它的 dist 是最终最短距离。理由——非负权保证绕路只会更长，全局最小的 unknown 节点已经不可能再被优化。

每个不变式都把"局部决策（取这个节点）"和"全局正确性（顺序合法/距离正确）"连起来。算法的整个执行就是不变式不断维护、不断扩展已确定集合的过程。

### BFS 为什么需要 visited 而拓扑排序不需要？

BFS 里同一个节点可能被多个邻居"发现"——A 和 B 同层都连着 C，A 处理时把 C 入队并标记，B 处理时再次发现 C，需要 visited 跳过。这里跳过的是**邻居 C**，不是 B 本身。同层节点 A 和 B 都必须出队处理，少一个就漏掉它连接的下层节点。

拓扑排序里入度归零才入队，每条入边精确触发一次减一，节点不可能被重复入队。判据本身就具有"恰好一次"的性质。

Dijkstra 介于两者之间——同一个节点可能被多次松弛成功，每次都 push 进堆，但 known 数组保证只在堆顶第一次见到它（且通过 dist 匹配）时才确定一次，后续重复出现的 stale entry 被 lazy deletion 跳过。

### "标记 = 最短已确定"

BFS 里第一次入队时距离就是最短，之后再被发现只能是同距离或更长的路径。标记拦住的是这些无意义的重复——和 Dijkstra 的 known 是同一个概念，只是 BFS 无权图所有边权为 1，第一次发现就是最短，不需要堆来排序。

把 BFS 的队列换成最小堆，BFS 就退化成了 Dijkstra（边权为 1 的特例）；把 Dijkstra 的边权全设为 1，Dijkstra 就退化成了 BFS。这不是巧合，是同一个框架在不同代价模型下的两种实例。

### 信息传递视角

三个算法都是**信息沿着边一跳一跳往外扩散**，每一跳建立在前一跳已确定的基础上。

- BFS 传递的信息是"距离 + 1"
- Dijkstra 传递的信息是"距离 + 边权"
- 拓扑排序传递的信息是"前驱已完成"（具体表现为 indegree 减一）

队列/堆只是把这个传递过程组织起来，确保"前面的已处理"这个不变式始终成立。换的只是"确定"的判据和数据结构，传递的本质不变。

### 环的处理

- **BFS**：visited 直接拦截，环不影响正确性，每个节点只处理一次。
- **拓扑排序**：环导致部分节点入度永远 ≠ 0，永远不会入队，最后 cnt < Nv 暴露环的存在。是顺带的环检测。
- **Dijkstra**：non-negative 权图上环不构成问题（绕环只会更长），known 拦住已确定节点；负权环会破坏正确性，需要 Bellman-Ford 处理。

这也解释了为什么拓扑排序专门要求 DAG，BFS 和 Dijkstra 不要求——前者依赖"剥离"的可终止性，环让剥离卡住；后两者只关心距离传递，环本身不影响。

### 选择哪个算法

如果只关心节点能否到达 → BFS/DFS 都行。
如果要无权图最短路 → BFS。
如果要带权图最短路（非负） → Dijkstra。
如果要带权图最短路（含负权但无负环） → Bellman-Ford / SPFA。
如果要任务执行顺序 + 环检测 → 拓扑排序（Kahn 或 DFS 后序逆序）。

判断的关键是问题问的是"距离"还是"顺序"，以及边权的性质。框架相通，钩子不同。

## 五、目标的差异

容易混淆的一点：BFS 最短路的目标是 **dist 数组**（每个节点的最短距离），拓扑排序的目标是**节点的线性序列**（出队顺序）。两者用的都是队列，逻辑结构相似，但解决的问题不同，输出不同。

Dijkstra 同理，目标是 dist 数组，节点的处理顺序只是副产品（恰好就是 Dijkstra Sequence 那道题要验证的东西）。
