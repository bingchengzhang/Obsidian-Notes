## 元框架：数据结构存在的理由

> 每种数据结构都是对"元素之间关系"的建模。结构性质（LIFO/FIFO/层级）是关系语义的结果，不是定义起点。

核心问题永远是：**如何管理"还没处理完的事情"？**

|结构|元素间关系|结构性质从何而来|
|---|---|---|
|栈|嵌套依赖：新问题必须先于旧问题解决|LIFO 是嵌套依赖的必然结果|
|队列|平等到达：先来先服务|FIFO 是公平调度的必然结果|
|链表|动态局部关联：关系随时变化|指针是"关系"的显式表达|
|树|层级派生：子问题由父问题产生|递归结构是层级关系的自然映射|

## 线性结构

### 数组

**一句话本质**：连续内存，下标即地址，随机访问 O(1)。 **本质洞察**：数组是"位置即语义"的结构——不需要显式存储关系，位置本身就携带了信息（如阶次）。代价是关系固定，动态调整代价高。

- 多项式表示：数组位置 = 阶次，如 `ax^4+bx^2` → `[a,0,b,0,0]`
    
- 支持：平均值、max、min、mid
    

### 链表

**一句话本质**：节点分散存储，靠指针串联，插入删除 O(1)，查找 O(n)。 **本质洞察**：链表是"关系显式化"的结构——把元素间的连接从隐式（位置相邻）变成显式（指针）。换来了关系的动态可变，失去了随机访问。

- 头节点 dummy node：统一删除逻辑，避免对 head 特判
    
- 双向链表：每个节点有 prev/next 两个指针
    
- 双向循环链表：⚠️ 待补充
    
- 多项式链表表示：结构体存 `{系数, 阶次}`，指针串联非零项
    
- 十字链表：二维稀疏矩阵，x/y 坐标 + 有效位标记，避免空间浪费
    
- 数组+链表结合：cursor 实现（用下标模拟指针）
    

### ADT 边界

**一句话本质**：ADT 错误 = 逻辑非法；实现错误 = 资源限制。

|错误类型|例子|本质|
|---|---|---|
|ADT 错误|空栈 Pop/Top|语义上无意义|
|实现错误|满栈 Push|数组有限，抽象无限|

### 栈 Stack

**一句话本质**：保存尚未完成的计算状态，LIFO 是嵌套依赖关系的必然结果。 **本质洞察**：

- 栈解决的问题是：当前任务依赖一个子任务，但子任务完成后还需要回来继续——必须保存"回来之后需要什么"。
    
- LIFO 不是人为规定，是嵌套结构的本质：最新产生的依赖必须最先解决。
    
- **显式栈与递归完全等价**：递归用系统栈隐式保存状态，显式栈手动保存同样的状态。消除递归 = 把隐式栈变成显式栈。
    
- 中缀→后缀转换是同一思想的应用：栈暂存"优先级更高、尚未结账"的操作符。
    

**核心机制：中缀→后缀转换**

- 栈 = 操作符的暂存区，LIFO 对应执行紧急度
    
- 出栈触发：新符号优先级 ≤ 栈顶 → 栈顶出栈（"结账"信号）
    
- 括号处理：`(` 入栈优先级极高，栈内优先级极低，充当"防火墙"
    
- 幂运算右结合：`^` 入栈优先级 > 栈内优先级，同类不触发弹出
    

规则总结：  
- 操作数 → 直接输出  
- 操作符 → 与栈顶比较，栈顶优先级 >= 新符号则弹出，直到不满足再入栈  
- ( → 直接入栈  
- ) → 弹出直到遇到 (，( 丢弃  
- 结束 → 清空栈  
- 平级时：先进的先输出（左结合）；^ 例外（右结合）

**工程底线**

- 封装：外部不得直接访问 Array / TopOfStack
    
- 强制预检：Push/Pop 前必须做错误检查
    

### 队列 Queue

**一句话本质**：FIFO，公平调度等待中的任务。 **本质洞察**：队列解决的问题是"任务之间没有依赖，只有先后"——所有任务平等，到达顺序即优先级。FIFO 是公平调度的唯一合理实现。循环队列是为了复用已出队的内存空间。

- 循环队列判满传统方法：浪费一个槽位
    
- 优化：增加 `Size` 字段，`Size==Capacity` 判满，`Size==0` 判空

## 树与递归

### 树的基本概念

**本质洞察**：树是"层级派生关系"的建模——父节点产生子节点，子问题由父问题分解而来。树的递归结构不是巧合，是层级关系的自然映射：对任意子树，根节点的性质和整棵树相同。

|术语|含义|
|---|---|
|degree|节点的子节点数|
|leaf|无子节点的节点|
|path|节点序列，无环|
|depth|根到当前节点的边数，depth(root)=0|
|height|当前节点到最远叶子的边数，height(leaf)=0|

关键关系：`height(root) = depth(deepest leaf)`

### 系统栈与递归

**一句话本质**：函数调用 = 栈帧压栈；返回 = 弹栈恢复现场。 **本质洞察**：递归和显式栈是同一件事的两种写法。递归让编译器管理栈（隐式），显式栈让程序员管理栈（显式）。能用递归解决的问题，一定能用显式栈改写，反之亦然。尾递归是特例：调用完不需要回来，栈帧可以复用，退化为循环。

**栈帧结构**：局部变量 + 返回地址 + 帧指针（Base Pointer）

**内存分区**

- 系统栈上的变量：函数返回自动释放
    
- `malloc` 堆上的变量：必须手动 `free`
    

**尾递归优化**

- 尾递归特征：递归调用是函数最后一步，旧栈帧无保留价值
    
- 编译器优化：将尾递归转为循环（goto → while）
    

// 原始尾递归（坏）  
void PrintList(List L) {  
    if (L != NULL) {  
        PrintElement(L->Element);  
        PrintList(L->next);  // 尾递归  
    }  
}  
​  
// 编译器等价转换（好）  
void PrintList(List L) {  
    while (L != NULL) {  
        PrintElement(L->Element);  
        L = L->next;  
    }  
}

**结论**：递归总能消除；非递归通常更快（省栈帧开销）

## 复杂度分析

### 渐进符号

**一句话本质**：O/Ω/Θ 描述增长趋势，不是等号，是集合关系（应写 ∈）。

|符号|含义|比喻|
|---|---|---|
|T(n) = O(f(n))|增长 ≤ f(n)|天花板（上界）|
|T(n) = \Omega(f(n))|增长 ≥ f(n)|地板（下界）|
|T(n) = \Theta(f(n))|增长 = f(n)|精准锁定（同阶）|

注意：`T(n) = 2T(n/2) + n` 中的等号是真等号（步数相等）；`T(n) = O(n)` 中是集合归属。

### 阶次排名（由慢到快）

O(1) < O(\log N) < O(\sqrt{N}) < O(N) < O(N\log N) < O(N^2) < O(2^N) < O(N!) < O(N^N)

- \log^k N 永远 < N^\epsilon（任意正数 ε），对数"长不高"
    
- 指数底数决定一切：O(3^N) \gg O(2^N)
    
- 斯特林公式：N! \approx \sqrt{2\pi N}(N/e)^N，介于指数和 N^N 之间
    

**判别法**：L = \lim_{N\to\infty} f(N)/g(N)，L=0 则 f<g，L=∞ 则 f>g，L=常数则同阶

### 主定理 Master Theorem

**一句话本质**：比较"老板汇总的活"和"底层小弟总量"，谁大谁决定复杂度。

T(n) = aT(n/b) + f(n)

- a：子问题数；b：规模缩减倍数；f(n)：当前层代价
    
- n^{\log_b a}：叶子节点总数（推导：树高 k=\log_b n，叶子数 a^k = n^{\log_b a}）
    

|情况|条件|结论|
|---|---|---|
|底层主导|n^{\log_b a} \gg f(n)|O(n^{\log_b a})|
|均衡|同阶|O(n^{\log_b a} \log n)|
|老板主导|f(n) \gg n^{\log_b a}|O(f(n))|

**例**：T(n)=9T(n/3)+n → n^{\log_3 9}=n^2 \gg n → O(n^2)
