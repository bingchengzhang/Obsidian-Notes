# Lab3 笔记：有限状态机 FSM 的本质与设计方法

## 1. 背景：为什么需要 FSM

很多电路不是只看当前输入就能决定输出。

例如“检测是否连续输入 3 个 `a`”，当前输入是 `a` 还不够，还必须知道之前已经连续看到几个 `a`。再比如“输入的 1 的个数是否超过 3”，当前位是 0 或 1 也不够，还要知道之前累计了几个 1。

这类问题的共同点是：

> ==输出不仅依赖当前输入，还依赖过去历史。==

组合逻辑没有记忆，只能处理当前输入；寄存器有记忆，但单独的寄存器不知道该如何更新。FSM 正是把“记忆”和“更新规则”组织起来的结构。

---

## 2. FSM 的本质：把无限历史压缩成有限状态

有限状态机的核心不是“画几个圈和箭头”，而是：

> ==用有限个状态概括所有对未来有用的历史信息。==

输入序列可以无限长，但不是所有历史都需要保留。我们只保留会影响后续判断的那部分信息。

例如检测“1 的个数是否超过 3”：

- 不需要记住完整输入串；
- 只需要知道目前 1 的个数是 0、1、2、3，还是已经超过 3。

所以设置 5 个状态：

| 状态 | 含义 | 输出 |
|---|---|---:|
| `S0` | 已看到 0 个 1 | 0 |
| `S1` | 已看到 1 个 1 | 0 |
| `S2` | 已看到 2 个 1 | 0 |
| `S3` | 已看到 3 个 1 | 0 |
| `S4` | 已超过 3 个 1 | 1 |

这里每个状态都不是随便起名，而是在保存一种==压缩后的历史信息==。

---

## 3. 状态、输入、输出、转移

FSM 四个核心元素：

| 元素 | 作用 |
|---|---|
| 状态 `state` | 保存过去历史的压缩结果 |
| 输入 `X` | 当前进入系统的新信息 |
| 转移 `next_state` | 当前状态和输入共同决定下一状态 |
| 输出 `Y` | 当前系统对外给出的结果 |

可以概括成：

```text
next_state = f(current_state, input)
output     = g(current_state)              // Moore 型
output     = g(current_state, input)       // Mealy 型
```

FSM 的关键是状态转移函数 `f`。它决定了历史如何被更新。

---

## 4. Moore 型与 Mealy 型

### 4.1 Moore 型

Moore 型输出只依赖当前状态：

```text
Y = g(state)
```

特点：

- 输出稳定；
- 不直接受输入毛刺影响；
- 通常需要多一个状态表达“刚刚满足条件”。

“1 的个数超过 3”如果要求 Moore 型，就必须有 `S4`。

原因：`S3` 表示“恰好 3 个 1”，输出必须是 0；当 `S3` 遇到输入 `1` 后，下一拍进入 `S4`，这时输出才变成 1。

### 4.2 Mealy 型

Mealy 型输出依赖当前状态和当前输入：

```text
Y = g(state, input)
```

如果用 Mealy 型，`S3` 遇到 `X=1` 时可以立刻输出 `Y=1`，因此不一定需要 `S4`。

所以“到 S3 就够不够”取决于题目要求。

- Moore 型：不够，需要 `S4`；
- Mealy 型：可以够，因为输出能看当前输入。

## 5. 例子：统计 1 的个数是否超过 3

题目：输入信号 `X ∈ {0,1}`，逐位统计输入中 1 的累计个数。若 1 的个数大于 3，则输出 `Y=1`，否则输出 `Y=0`。

采用 Moore 型 FSM。

### 5.1 状态设计

```text
S0：累计 0 个 1
S1：累计 1 个 1
S2：累计 2 个 1
S3：累计 3 个 1
S4：累计超过 3 个 1，接受态
```

`S4` 是==吸收态==。一旦进入 `S4`，说明“已经超过 3 个 1”这个事实成立，后续无论输入 0 还是 1，都不可能改变这个事实，所以一直留在 `S4`。

### 5.2 状态转移表

| 当前状态 | 含义 | `X=0` | `X=1` | 输出 `Y` |
|---|---|---|---|---:|
| `S0` | 0 个 1 | `S0` | `S1` | 0 |
| `S1` | 1 个 1 | `S1` | `S2` | 0 |
| `S2` | 2 个 1 | `S2` | `S3` | 0 |
| `S3` | 3 个 1 | `S3` | `S4` | 0 |
| `S4` | >3 个 1 | `S4` | `S4` | 1 |

### 5.3 状态图文字版

```text
X=1        X=1        X=1        X=1
S0  ---->  S1  ---->  S2  ---->  S3  ---->  S4
^          ^          ^          ^          |
| X=0      | X=0      | X=0      | X=0      | X=0/1
+----------+----------+----------+----------+
```

更准确地说，每个 `S0~S3` 在 `X=0` 时自环，`S4` 在 `X=0` 和 `X=1` 时都自环。

---

## 6. 吸收态是什么意思

吸收态就是：

> ==一旦进入，就再也不会离开的状态。==

在上面的例子里，`S4` 表示“已经超过 3 个 1”。这个事实一旦成立，后续输入任何位都不会让它重新变成“不超过 3 个”。

所以：

```text
S4 --X=0--> S4
S4 --X=1--> S4
```

如果 `S4` 在 `X=0` 时退回 `S3`，那语义就变成了“某个窗口里的 1 的数量”，而不是“累计 1 的数量”。这是完全不同的问题。

---

## 7. 三段式 FSM 写法

SystemVerilog 中常用三段式：

1. 第一段：状态寄存器；
2. 第二段：下一状态组合逻辑；
3. 第三段：输出组合逻辑。

### 7.1 状态定义

```systemverilog
typedef enum logic [2:0] {
    S0, S1, S2, S3, S4
} state_t;

state_t current_state, next_state;
```

`enum` 的价值是让状态有名字，而不是直接写 `3'b000`、`3'b001`。这提高可读性，也降低编码错误概率。

### 7.2 第一段：状态寄存器

```systemverilog
always_ff @(posedge clk or negedge rstn) begin
    if (!rstn)
        current_state <= S0;
    else
        current_state <= next_state;
end
```

这一段只做一件事：在时钟边沿把 `next_state` 存进状态寄存器。

它本质上是一组 D 触发器，不应该在这里写复杂判断。复杂判断放到第二段。

### 7.3 第二段：状态转移逻辑

```systemverilog
always_comb begin
    next_state = current_state;   // 默认保持，防止 latch

    case (current_state)
        S0: if (X) next_state = S1;
        S1: if (X) next_state = S2;
        S2: if (X) next_state = S3;
        S3: if (X) next_state = S4;
        S4: next_state = S4;
        default: next_state = S0;
    endcase
end
```

`next_state = current_state` 是默认赋值，用来避免某些分支没有赋值导致 latch。

`default: next_state = S0` 是非法状态恢复。硬件上状态寄存器可能因为复位、毛刺或综合编码进入未定义状态，`default` 可以让系统回到合法轨道。

### 7.4 第三段：输出逻辑

```systemverilog
always_comb begin
    Y = (current_state == S4);
end
```

这是 Moore 型输出，只看当前状态。`S4` 是接受态，所以只有 `current_state == S4` 时输出 1。

## 8. enum + case 与数组查表

### 8.1 enum + case

优点：

- 状态含义清楚；
- 适合状态少、转移逻辑有明显语义的 FSM；
- 便于调试和写报告；
- 容易加入 `default` 进行非法状态恢复。

缺点：

- 状态很多时 `case` 会变长；
- 若转移规则非常规整，手写 `case` 可能重复。

### 8.2 数组查表

数组查表可以把转移写成表：

```verilog
next_state = transition_table[current_state][input];
```

优点：

- 适合状态很多、规则规整的 FSM；
- 表结构紧凑；
- 便于自动生成。

缺点：

- 可读性差；
- 状态语义不如 `enum + case` 直观；
- 初学阶段不利于理解状态转移本质。

本实验更适合 `enum + case`，因为重点是理解状态语义，而不是压缩代码。

## 9. FSM 编码：binary、one-hot、Gray

`enum` 只是让状态有符号名字，不等于强制综合工具使用某种编码。

综合工具可能根据策略选择不同编码：

| 编码方式 | 特点 | 适用场景 |
|---|---|---|
| binary | 位数少，寄存器省 | 状态多、资源敏感 |
| one-hot | 每个状态一个 bit，译码快 | FPGA 中常见，状态不太多 |
| Gray | 相邻状态只变一位 | 跨时钟域、减少毛刺 |

对小型 FSM 来说，这些差异不大。真正要掌握的是：状态名是逻辑语义，编码是硬件实现。不要把二者混为一谈。

---

## 10. 常见错误：把位反转当移位

例如：

```verilog
always @(posedge clk) begin
    if (~rstn)
        state <= 2'b01;
    else
        state[1:0] <= state[0:1];
end
```

`state[1:0] <= state[0:1]` 不是移位，而是==两位互换==。

如果当前状态是 `2'b01`：

```text
01 -> 10 -> 01 -> 10 -> ...
```

电路会在两个状态之间来回振荡，无法表达正常 FSM 的状态推进。

更严重的是非法状态无法恢复：

```text
00 -> 00
11 -> 11
```

如果寄存器因为异常进入 `00` 或 `11`，它会永远困在非法状态。正确 FSM 应该通过 `case default` 或非法状态检测让系统回到合法初始状态。

## 11. FSM 与“有限记忆”思维

FSM 的抽象很重要：它不是保存全部历史，而是保存==对未来决策有用的最小历史==。

检测连续 3 个 `a` 时，不需要保存完整字符串，只需要保存“当前连续 a 的个数是 0、1、2、还是已经达到 3”。统计 1 的个数是否超过 3 时，也不需要保存每一位输入，只需要保存累计数量落在哪个区间。

这是一种压缩思想：

- 无限输入序列被压缩成有限状态；
- 复杂历史被压缩成当前决策所需的信息；
- 状态转移负责不断更新这份压缩记忆。

这和很多算法思想相通。比如动态规划保存子问题状态，并查集路径压缩保存代表元，缓存系统保存最近有用的信息。它们都在做一件事：丢掉无关历史，保留决策信息。

---

## 12. 思维提升：FSM 是控制复杂过程的基本框架

FSM 不只是数字逻辑实验里的一个题型。它是一种通用的系统建模方式。

只要一个过程满足：

- 有阶段；
- 每个阶段行为不同；
- 阶段之间根据条件切换；
- 过去历史会影响下一步；

就可以用 FSM 建模。

例如：

- CPU 指令执行：取指、译码、执行、访存、写回；
- 乘法器/除法器：空闲、计算、完成；
- 通信协议：等待请求、传输、确认、错误恢复；
- 软件界面：未登录、登录中、已登录、异常状态。

所以 FSM 的核心价值是：

> ==把连续复杂过程离散成有限阶段，再用转移规则组织起来。==

---

## 13. 一句话总结

FSM 的本质是用有限状态压缩无限历史，用状态转移更新记忆，用输出逻辑表达当前系统语义。写 FSM 时，状态不是编码，而是对“过去对未来有什么影响”的抽象。
