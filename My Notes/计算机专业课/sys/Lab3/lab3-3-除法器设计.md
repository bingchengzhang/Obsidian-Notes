# Lab3-3 笔记：32 位无符号除法器设计

## 1. 背景：除法为什么适合用迭代状态机

除法比加法、乘法更复杂，因为它不是一次局部运算就能完成。除法需要不断判断“当前余数够不够减除数”，并根据判断结果逐位确定商。

如果直接做一个完全组合的 32 位除法器，硬件路径会很长，延迟大，资源也多。实验中采用迭代式除法器：每个时钟周期只处理一位，重复 32 次得到结果。

这正是状态机适合处理的问题：

- 每一步规则相同；
- 每一步依赖上一步结果；
- 整体任务需要多个周期完成；
- 外部只需要最终结果，不关心中间过程。

---

## 2. 除法的本质：逐位确定“够不够减”

除法的数学语义是：

```text
Dividend = Divisor × Quotient + Remainder
0 <= Remainder < Divisor
```

也就是：被除数可以拆成“若干个除数”加上“剩下不能再减的部分”。

竖式除法的本质不是神秘的计算技巧，而是逐位回答一个问题：

> ==当前这段数够不够减除数？==

在二进制里，每一位商只能是 0 或 1，所以判断更简单：

- 够减：这一位商为 1，余数减去除数；
- 不够减：这一位商为 0，余数保持当前值。

十进制除法需要“猜商”，二进制除法把“猜商”退化成了“比较”。这就是二进制除法适合硬件实现的原因。

---

## 3. 例子：13 ÷ 3

用 4 位演示：

```text
Dividend = 1101₂ = 13
Divisor  = 0011₂ = 3
```

从高位到低位处理被除数：

```verilog
i = 3: remainder = 0<<1 | 1 = 1,  1 < 3,  商 0，余数 = 1
i = 2: remainder = 1<<1 | 1 = 3,  3 >= 3, 商 1，余数 = 0
i = 1: remainder = 0<<1 | 0 = 0,  0 < 3,  商 0，余数 = 0
i = 0: remainder = 0<<1 | 1 = 1,  1 < 3,  商 0，余数 = 1
```

最终：

```text
商 = 0100₂ = 4
余数 = 0001₂ = 1
验证：13 = 3 × 4 + 1
```

注意这里的商位是从高到低依次确定的。高位商决定了后续余数，如果顺序反过来，后面的判断就没有正确基础。

---

## 4. 核心操作：余数左移并拼入下一位

每轮最关键的一步是：

```verilog
shifted = {remainder, dividend[work_cnt]};
```

也可以写成：

```verilog
shifted = (remainder << 1) | dividend[work_cnt];
```

它的含义是：把上一轮的余数左移一位，再把被除数的当前位拉下来。

这和手算竖式里的“拉下一位”完全对应。

为什么必须左移？因为余数不是孤立的一位，而是已经处理过的高位信息。新拉下来的位处在最低位，旧余数必须整体升高一个位权，才能和新位组成正确的数。

如果不左移，就相当于把竖式里的“3 拉下 4 得到 34”错误地理解成“3 + 4”，位权关系全乱。

---

## 5. 余数的本质：滚动状态，而不是原数截片

余数不是被除数某一段的简单截取。它是一个滚动状态：

> ==当前已经处理过的高位，扣掉已经被整除部分之后剩下的量。==

每轮都做四件事：

1. 余数左移，拼入被除数当前位；
2. 比较当前值和除数；
3. 如果够减，商位写 1，余数减除数；
4. 如果不够减，商位写 0，余数保留。

所以除法器内部最重要的寄存器不是商，而是 `remainder`。商只是每轮判断结果的记录；余数才是把每一轮连接起来的状态。

---

## 6. 硬件结构：数据通路 + 控制 FSM

除法器可以分成两部分：

- 数据通路：寄存器、比较器、减法器、移位/拼接逻辑；
- 控制器：FSM 和计数器，决定每一拍执行哪一步。

典型三态结构：

```verilog
IDLE:
    等待 start
    锁存 dividend 和 divisor
    remainder = 0
    quotient  = 0
    work_cnt  = 31

WORK:
    shifted = {remainder, dividend[work_cnt]}
    sub_ok  = shifted >= divisor

    if (sub_ok) begin
        remainder <= shifted - divisor
        quotient[work_cnt] <= 1
    end else begin
        remainder <= shifted
        quotient[work_cnt] <= 0
    end

    work_cnt <= work_cnt - 1

FINAL:
    finish = 1
    输出 quotient 和 remainder
```

FSM 控制“什么时候开始、什么时候迭代、什么时候结束”；数据通路负责“这一拍具体算什么”。

这就是硬件设计里常见的==控制通路与数据通路分离==。

---

## 7. 为什么 `shifted` 需要 33 位

`remainder` 是 32 位时，左移一位可能产生第 33 位。

如果仍然用 32 位保存，最高位会被截断。这样再和 32 位 `divisor` 比较，就可能误判。

例如真实的 `shifted` 已经大于除数，但因为最高位被截掉，硬件看到的值反而变小，导致本该写商 1 的位置写成 0。

所以应当使用 33 位中间量：

```verilog
logic [32:0] shifted;
logic [32:0] remainder_reg;
```

硬件里不能只想数学值，还要想位宽。==位宽不足就是信息丢失==。

---

## 8. 为什么从高位到低位处理

除法必须从高位开始，因为商的高位权重最大。

高位商是否为 1，会直接改变后续余数；后续低位是在这个余数基础上继续处理的。如果先从低位做，就不知道高位是否已经消耗掉一部分被除数，也就无法得到正确余数。

乘法可以从低位乘起，是因为每一位乘法贡献可以独立累加；除法不行，因为每一位判断都依赖前面留下的余数。

这就是乘法器和除法器方向相反的根本原因。

---

## 9. 和乘法器的统一理解

| 对比项 | 乘法器 | 除法器 |
|---|---|---|
| 每轮判断 | 乘数当前位是否为 1 | 当前余数是否够减除数 |
| 判断为真 | 加被乘数 | 减除数，商写 1 |
| 判断为假 | 加 0 | 不减，商写 0 |
| 处理方向 | 通常从低位到高位 | 必须从高位到低位 |
| 跨轮状态 | 部分积 | 余数 |
| 本质 | 逐位累加贡献 | 逐位确定商位 |

两者的统一模式是：

> ==把一个 N 位大问题拆成 N 个 1 位判断，用寄存器保存跨轮状态。==

这就是迭代硬件的核心套路。

---

## 10. 除 0 问题

无符号除法器必须考虑 `divisor == 0`。

数学上除 0 没有定义。硬件里如果不处理，比较逻辑可能每轮都判断“够减”，最终得到没有意义的商和余数。

常见处理方式有三种：

1. 直接约定输入不会出现除 0；
2. 检测到除 0 时输出特殊值，例如商全 1、余数等于被除数；
3. 增加 `error` 或 `valid` 信号，告诉外部结果无效。

实验如果没有要求，可以在报告中说明测试输入避开 `divisor = 0`；但从完整设计角度看，除 0 检测是必要的。

---

## 11. 思维提升：除法器训练的是“状态化计算”

这次除法器不是为了让你记住某段代码，而是让你理解一种计算转化方式：

- 数学上，除法是一个整体关系；
- 算法上，它被拆成逐位比较和减法；
- 硬件上，它被拆成数据通路和 FSM；
- 时序上，它被拆成 32 个时钟周期；
- 接口上，它被封装成 `start / finish`。

这就是从数学问题到硬件系统的完整降维过程。

真正重要的是：复杂计算不一定要一次完成。只要能把问题拆成重复的小步骤，并用寄存器保存跨步骤状态，就可以用有限硬件资源完成任意位宽的计算。

这和 FSM 的思想是同一个内核：

> ==无限或复杂的过程，被压缩成有限状态与重复转移。==

---

## 12. 一句话总结

32 位无符号除法器的本质，是用 `remainder` 保存跨轮状态，从高位到低位逐位判断“够不够减”，再用 FSM 把 32 次判断组织成一次完整的除法任务。
